# ELD Compliance & HOS Data Tampering Security Assessment
**Project:** Golden Feather ELD  
**Evaluation Focus:** Federal Motor Carrier Safety Administration (FMCSA) 49 CFR Part 395 Data Integrity  
**Threat Scenario:** Insider Threat / Adversarial Driver with Physical Device Access  
**Evaluation Standard:** OWASP MASVS v2.0 & ELD Technical Specifications Security Criteria  
**Status:** Deep Technical Assessment & Threat Verification  
**Date:** October 2026  

---

## 1. Executive Summary

This assessment evaluates the resilience of the **Golden Feather ELD** mobile system against deliberate data tampering, fraudulent record modification, telemetry spoofing, and compliance evasion.

Commercial ELD applications are unique: the primary adversary is often an authenticated, legitimate user (a fatigued or incentivized driver) who has physical possession of the mobile device and may seek to falsify duty status, alter driving hours, manipulate timestamps, or suppress vehicle motion events to evade FMCSA Hours of Service (HOS) limits.

### Assessment Parameters:
We evaluate 20 specific tampering scenarios under the assumption that an attacker has:
1. Physical access to a shared commercial smartphone/tablet.
2. A valid, low-privilege driver account.
3. Access to application-local storage via device debugging, backup, or rooting tools.
4. The ability to manipulate device system time.
5. The ability to run mock location apps or simulate GPS coordinates.
6. The ability to operate a rogue Bluetooth Low Energy (BLE) peripheral.
7. The ability to control or interrupt device network connectivity (Airplane Mode).

## 2. Threat Analysis Across 20 Tampering Vectors

---

### Threat 1: Unauthorized Modification of HOS Logs
- **Trust Boundary:** Local Storage (Hive `events_box` / `daily_logs_cache_box`) vs. Server REST API.
- **Implementation Trace:** HOS logs are cached in [`LocalDatabaseService`](file:///d:/Flutter%20projects/golden_feather_eld/lib/core/services/local_database_service.dart#L12) and manipulated via [`EldDutyStatusBackend`](file:///d:/Flutter%20projects/golden_feather_eld/lib/backend/adapters/eld_engine/sub/eld_duty_status_backend.dart).
- **Existing Safeguards:** Local edits do not overwrite immutable server records directly. Editing duty events triggers `PUT /eld/duty-status/{id}` which sends the update to the server.
- **Attacker Prerequisites:** Root access to mobile device or access to unencrypted local SQLite/Hive files.
- **Realistic Exploitability:** **MEDIUM**. A local database modification alters what is rendered in the UI graph grid temporarily, but the server rejects unauthorized changes during synchronization unless authenticated and within allowable FMCSA edit rules.
- **Backend Verification Requirements:** Backend must verify that original automated ELD driving events (`DRIVING` status generated by ECM motion) are strictly non-editable, and that only manual annotations or non-driving statuses can be edited with mandatory reason codes.
- **Defensive Controls:** Encrypt Hive and SQLite databases with AES-256 keys in hardware Keystore. Verify hash signatures of local records before rendering.
- **Regression Tests:** Verify that editing an ECM-generated driving event in local cache is rejected upon sync.

### Threat 2: Manipulation of Duty Status Timestamps
- **Trust Boundary:** Device System Clock vs. [`TrustedTimeProvider`](file:///d:/Flutter%20projects/golden_feather_eld/lib/core/time/trusted_time_provider.dart) vs. Server `Date` Header.
- **Implementation Trace:** Duty status records read time from `ref.read(trustedTimeProvider).currentTime`. When online, [`TimeDriftInterceptor`](file:///d:/Flutter%20projects/golden_feather_eld/lib/backend/http/interceptors/time_drift_interceptor.dart) anchors time to the HTTP server `Date` header. When offline after restart, [`MonotonicTrustedTimeProvider:78-80`](file:///d:/Flutter%20projects/golden_feather_eld/lib/core/time/trusted_time_provider.dart#L78-L80) calculates elapsed time using `DateTime.now().difference(restoredDeviceWall)`.
- **Existing Safeguards:** While running, a monotonic `Stopwatch` prevents time manipulation.
- **Attacker Prerequisites:** Force-stop app while offline, alter Android system time, relaunch app.
- **Realistic Exploitability:** **HIGH (Offline Only)**. The offline time anchor adopts the manipulated system clock offset during cold boot without internet. Duty status changes created before reconnecting carry the manipulated timestamp.
- **Backend Verification Requirements:** The server must calculate drift between the event timestamp and server ingestion time. Any offline events with timestamps older than allowable clock drift thresholds must be flagged for manual supervisor review.
- **Defensive Controls:** Use `SystemClock.elapsedRealtime()` via Android platform channel to compute monotonic elapsed duration across app lifecycles. Cross-check time against GPS NMEA UTC sentences.
- **Regression Tests:** Simulate app launch with altered system clock while offline; verify trusted time state changes to `unavailable`.

### Threat 3: Forged GPS Tracking Events
- **Trust Boundary:** Android `LocationManager` vs. [`TrackingForegroundService.kt`](file:///d:/Flutter%20projects/golden_feather_eld/android/app/src/main/kotlin/com/goldenfeather/eld/TrackingForegroundService.kt).
- **Implementation Trace:** Location updates arrive in native Kotlin service and are evaluated before transmission.
- **Existing Safeguards:** Service inspects `location.isFromMockProvider` on Android.
- **Attacker Prerequisites:** Developer options enabled or root hooks (e.g. LSPosed / Magisk) that hook `LocationManager` to return `isFromMockProvider = false`.
- **Realistic Exploitability:** **MEDIUM**. Standard mock location apps are detected and blocked. Advanced kernel-level or root-based location spoofing bypasses standard Android checks.
- **Backend Verification Requirements:** Backend must perform geofence and plausibility validation: reject teleports (impossible speed between two points, e.g. >100 mph distance velocity).
- **Defensive Controls:** Verify raw GPS NMEA sentences (e.g. satellite count, dilution of precision, SNR) via `GnssStatus.Callback`.
- **Regression Tests:** Inject mock locations via ADB; verify service discards mock points.

### Threat 4: Replayed Bluetooth ELD Messages
- **Trust Boundary:** External BLE Peripheral vs. [`BluetoothPlugin.kt`](file:///d:/Flutter%20projects/golden_feather_eld/android/app/src/main/kotlin/com/goldenfeather/eld/BluetoothPlugin.kt).
- **Implementation Trace:** Characteristic `0000ffe1-...` notifications deliver ASCII strings over GATT.
- **Existing Safeguards:** None. The plugin passes raw strings to the Flutter event channel without sequence counters, timestamps, or nonce verification.
- **Attacker Prerequisites:** BLE capture/replay tool (e.g. Ubertooth, HackRF, or smartphone with nRF Connect).
- **Realistic Exploitability:** **HIGH**. An attacker can record valid stationary BLE packets and replay them while the vehicle is driving.
- **Backend Verification Requirements:** Correlate BLE vehicle telemetry with cellular/GPS tracking telemetry. If GPS speed > 15 mph but BLE reports 0 mph, flag ELD discrepancy malfunction.
- **Defensive Controls:** Enforce monotonic message sequence numbers and cryptographic HMACs on all ELD telemetry frames.
- **Regression Tests:** Inject replayed BLE packets with identical sequence IDs; verify rejection.

### Threat 5: Fake Vehicle Movement Events
- **Trust Boundary:** BLE ELD Adapter / Vehicle ECM vs. Driving Status Engine.
- **Implementation Trace:** Automatic transition to `DRIVING` occurs when speed exceeds 5 mph (8 km/h) per FMCSA rules.
- **Existing Safeguards:** Evaluates speed telemetry from BLE and GPS.
- **Attacker Prerequisites:** Rogue BLE peripheral or disconnection of BLE adapter.
- **Realistic Exploitability:** **HIGH (via BLE)**. If a driver operates a rogue BLE broadcaster sending speed = 0, the app fails to automatically switch to `DRIVING`.
- **Backend Verification Requirements:** The server must ingest GPS position data concurrently and automatically generate unassigned driving events if GPS detects movement while ELD reports stationary.
- **Defensive Controls:** Implement dual-source speed validation (BLE speed cross-checked with GPS speed).
- **Regression Tests:** Simulate high GPS speed with zero BLE speed; verify diagnostic alert triggers.

### Threat 6: Unauthorized Driver Switching
- **Trust Boundary:** Driver UI vs. [`AuthNotifier`](file:///d:/Flutter%20projects/golden_feather_eld/lib/features/auth/presentation/providers/auth_state_provider.dart).
- **Implementation Trace:** Driver switching requires explicit authentication or co-driver PIN.
- **Existing Safeguards:** [`SessionEpoch`](file:///d:/Flutter%20projects/golden_feather_eld/lib/core/session/session_epoch.dart) increments on identity boundaries. Stale requests from Driver A are invalidated.
- **Attacker Prerequisites:** Knowing co-driver's credentials.
- **Realistic Exploitability:** **LOW**. Identity boundary logic is strictly enforced in Flutter state.
- **Backend Verification Requirements:** Backend must enforce that two drivers cannot simultaneously claim active driving status in the same vehicle.
- **Defensive Controls:** Implement biometric prompt (Face/Fingerprint) before switching active driver on shared tablets.
- **Regression Tests:** Verify `SessionEpoch` increments and all presentation state transitions cleanly during switch.

### Threat 7: Cross-Driver Access to ELD Logs on Shared Devices
- **Trust Boundary:** Device Filesystem vs. UI Presentation.
- **Implementation Trace:** [`AuthRepositoryImpl._clearLocalData()`](file:///d:/Flutter%20projects/golden_feather_eld/lib/features/auth/data/repositories/auth_repository_impl.dart#L102) clears SecureStorage credentials, but retains Hive `daily_logs_cache_box`.
- **Existing Safeguards:** UI queries logs filtered by driver ID when online.
- **Attacker Prerequisites:** Driver B logs into the app on the same device after Driver A logs out while in offline mode.
- **Realistic Exploitability:** **MEDIUM**. Driver B may view cached logs or draft signatures belonging to Driver A if offline repository queries do not strictly filter by driver ID.
- **Backend Verification Requirements:** Ensure API endpoints require valid authentication and verify tenant/driver ownership for every GET request.
- **Defensive Controls:** Purge all cached daily logs and draft signatures upon logout in `AuthRepositoryImpl`.
- **Regression Tests:** Log in as Driver A, cache records, logout, log in as Driver B offline; verify Driver A logs are absent.

### Threat 8: Modification of Offline Mutation Queues
- **Trust Boundary:** SQLite Database (`offline_queue.db`) vs. Sync Engine.
- **Implementation Trace:** [`SQLiteOfflineQueue`](file:///d:/Flutter%20projects/golden_feather_eld/lib/features/sync/data/repositories/sqlite_offline_queue.dart) writes pending mutations to an unencrypted SQLite database.
- **Existing Safeguards:** Database is inside private app sandbox.
- **Attacker Prerequisites:** Rooted Android device or forensic physical extraction.
- **Realistic Exploitability:** **MEDIUM-HIGH**. An attacker can open `offline_queue.db` with SQLite editor and alter status, timestamps, or odometer readings before reconnecting to the internet.
- **Backend Verification Requirements:** Backend must validate internal consistency of all synced mutation fields against current server vehicle state.
- **Defensive Controls:** Encrypt `offline_queue.db` using SQLCipher and sign queue entries with an HMAC using a key in SecureStorage.
- **Regression Tests:** Corrupt or modify an offline mutation row; assert that HMAC mismatch sends the row to `quarantine`.

### Threat 9: Duplicate or Replayed Certification Requests
- **Trust Boundary:** [`CertifyLogNotifier`](file:///d:/Flutter%20projects/golden_feather_eld/lib/features/logs/presentation/providers/certify_log_provider.dart) vs. `POST /eld/daily-logs/{id}/certify`.
- **Implementation Trace:** Submits `{ certified: true, signatureImage: "..." }`.
- **Existing Safeguards:** State machine blocks UI duplicate taps while `isLoading = true`.
- **Attacker Prerequisites:** Capturing network traffic and replaying POST request.
- **Realistic Exploitability:** **LOW**. Replaying a certification on an already-certified log is idempotent or rejected by the server with HTTP 409 (`ALREADY_CERTIFIED`).
- **Backend Verification Requirements:** Backend must maintain an immutable certification audit trail with server timestamps.
- **Defensive Controls:** Include an idempotency key (UUID) in the certification payload.
- **Regression Tests:** Submit duplicate certification calls in parallel; verify single server application.

### Threat 10: Signature Substitution Between Daily Logs
- **Trust Boundary:** Signature Canvas vs. Local Storage vs. API Payload.
- **Implementation Trace:** Draft signature is saved under `sig_draft:${logId}` in [`LogLocalDataSource`](file:///d:/Flutter%20projects/golden_feather_eld/lib/features/logs/data/datasources/log_local_data_source.dart#L60).
- **Existing Safeguards:** Signatures are keyed per `logId`.
- **Attacker Prerequisites:** Access to local unencrypted Hive cache.
- **Realistic Exploitability:** **MEDIUM**. An attacker can copy a signature Base64 string from one log and submit it for another log or another driver.
- **Backend Verification Requirements:** Verify driver authorization before accepting certification.
- **Defensive Controls:** Cryptographically bind the signature to the specific log using an asymmetric key pair.
- **Regression Tests:** Attempt submitting Driver A's signature for Driver B's log; verify rejection.

### Threat 11: Alteration of Odometer Readings
- **Trust Boundary:** BLE ECM Bus vs. Duty Status Payload.
- **Implementation Trace:** Odometer is read from vehicle telemetry and injected into duty status records.
- **Existing Safeguards:** None on the client.
- **Attacker Prerequisites:** Rogue BLE device or manual field edit.
- **Realistic Exploitability:** **HIGH (via BLE)**. App accepts odometer values from unauthenticated BLE peripheral.
- **Backend Verification Requirements:** Backend must reject decreasing odometer readings (odometer rollback detection).
- **Defensive Controls:** ECM hardware authentication; server-side monotonic odometer validation.
- **Regression Tests:** Submit an event with odometer less than previous certified event; verify server rejection.

---

### Threat 12: Alteration of Engine Hour Readings
- **Trust Boundary:** BLE ECM Bus vs. Duty Status Payload.
- **Implementation Trace:** Engine hours are extracted from BLE stream and appended to duty events.
- **Existing Safeguards:** None on client.
- **Attacker Prerequisites:** Rogue BLE peripheral.
- **Realistic Exploitability:** **HIGH (via BLE)**. Same as Threat 11.
- **Backend Verification Requirements:** Server must verify engine hours never decrease over time.
- **Defensive Controls:** Server-side monotonically increasing checks; secure BLE bonding.
- **Regression Tests:** Submit decreasing engine hours; verify rejection.

### Threat 13: Removal of Compliance-Critical Events
- **Trust Boundary:** Local Storage vs. Sync Dispatcher.
- **Implementation Trace:** [`SQLiteOfflineQueue.removeEvent`](file:///d:/Flutter%20projects/golden_feather_eld/lib/features/sync/data/repositories/sqlite_offline_queue.dart#L243) deletes events from pending queue upon successful dispatch.
- **Existing Safeguards:** The `duty_event_journal` table records all transitions immutably.
- **Attacker Prerequisites:** Root access to SQLite database file.
- **Realistic Exploitability:** **LOW-MEDIUM**. While an attacker could drop rows in local SQLite, server records are immutable.
- **Backend Verification Requirements:** Ensure sequence numbers are gapless; detect missing event sequence IDs.
- **Defensive Controls:** Write events to an append-only, HMAC-chained journal table.
- **Regression Tests:** Verify that deleting a pending event leaves an audit record in `duty_event_journal`.

### Threat 14: Unauthorized Editing of Certified Logs
- **Trust Boundary:** UI Form Provider vs. Remote Backend.
- **Implementation Trace:** Certified logs are displayed with a certified badge. Edits to certified logs require re-certification.
- **Existing Safeguards:** Server rejects updates to certified logs with HTTP 409 Conflict.
- **Attacker Prerequisites:** Low-privilege driver account.
- **Realistic Exploitability:** **LOW (Mitigated by Backend)**.
- **Backend Verification Requirements:** Backend strictly returns HTTP 409 if an edit is attempted on a certified log without a prior un-certify operation.
- **Defensive Controls:** Client disables edit controls when `log.certified == true`.
- **Regression Tests:** Attempt sending `PUT /eld/duty-status/{id}` against a certified log; verify 409 handling.

### Threat 15: Manipulation of Event Ordering
- **Trust Boundary:** Offline Queue Priority Ordering vs. Server Ingestion.
- **Implementation Trace:** Events in `sqlite_offline_queue.dart` are ordered by `priority ASC, createdAt ASC`.
- **Existing Safeguards:** Event sequence IDs and monotonic counters maintain relative ordering.
- **Attacker Prerequisites:** Altering `createdAt` timestamps in local SQLite database.
- **Realistic Exploitability:** **MEDIUM**.
- **Backend Verification Requirements:** Server re-orders events based on chronological transition timestamps rather than arrival order.
- **Defensive Controls:** Include sequence counter (`seq`) generated at creation time.
- **Regression Tests:** Enqueue events out of order; verify server reconstructs correct chronological sequence.

### Threat 16: Reuse of Stale Authentication Tokens
- **Trust Boundary:** Local Secure Storage vs. [`AuthInterceptor`](file:///d:/Flutter%20projects/golden_feather_eld/lib/backend/http/interceptors/auth_interceptor.dart).
- **Implementation Trace:** Cookie `JSESSIONID` attached to all requests.
- **Existing Safeguards:** `SessionEpoch` and `credentialGeneration` discard outdated responses.
- **Attacker Prerequisites:** Replaying an old cookie extracted from a rooted phone.
- **Realistic Exploitability:** **LOW**. The server terminates sessions upon logout or expiration; replayed cookies receive HTTP 401.
- **Backend Verification Requirements:** Enforce server-side session timeouts and single-session concurrency per driver.
- **Defensive Controls:** Clear session credentials immediately upon 401 or logout.
- **Regression Tests:** Test request rejection with expired session cookie.

### Threat 17: Submission of Offline Events Under the Wrong Driver Identity
- **Trust Boundary:** [`TraccarRemoteEventDispatcher._authorize`](file:///d:/Flutter%20projects/golden_feather_eld/lib/features/sync/data/repositories/traccar_remote_event_dispatcher.dart#L70).
- **Implementation Trace:** Resolves event ownership via [`EventOwnershipResolver`](file:///d:/Flutter%20projects/golden_feather_eld/lib/features/sync/domain/entities/event_ownership.dart).
- **Existing Safeguards:** If `ownership.driverId != sessionDriverId`, event is quarantined (`deferredOwnerMismatch`). In addition, `AuthInterceptor` checks `expectedOwnerKey`.
- **Attacker Prerequisites:** Driver B logs in while Driver A's events are pending in queue.
- **Realistic Exploitability:** **NEGLIGIBLE (Strongly Mitigated)**. Two independent software fences prevent transmission under mismatched identity.
- **Backend Verification Requirements:** Verify request payload `driverId` matches authenticated session.
- **Defensive Controls:** Existing dual-layer client fence (`_authorize` and `AuthInterceptor`).
- **Regression Tests:** `dispatch_ownership_test.dart` confirms that mismatched events are quarantined and never sent over HTTP.

### Threat 18: Loss of Audit Trail Integrity
- **Trust Boundary:** Local Audit Box vs. Server Compliance Log.
- **Implementation Trace:** HOS changes record audit entries in Hive `hos_audit_box`.
- **Existing Safeguards:** System records change reason, timestamp, and modifying driver.
- **Attacker Prerequisites:** Root access to delete local Hive audit box.
- **Realistic Exploitability:** **LOW**. Primary legal audit trail resides on carrier server.
- **Backend Verification Requirements:** Carrier backend must maintain an immutable, tamper-evident audit log of all changes per FMCSA 49 CFR Part 395.
- **Defensive Controls:** Stream audit records directly to server upon creation.
- **Regression Tests:** Verify that editing an event creates an accompanying audit entry.

---

### Threat 19: Incorrect Reconciliation Between Local and Server Records
- **Trust Boundary:** Offline Sync Engine vs. Remote Server Database.
- **Implementation Trace:** Server responses update local cache via `SyncEngine`.
- **Existing Safeguards:** Server-assigned IDs overwrite client temporary UUIDs.
- **Attacker Prerequisites:** Interrupted network connectivity during two-way sync.
- **Realistic Exploitability:** **LOW**.
- **Backend Verification Requirements:** Idempotent reconciliation matching on client-provided `uniqueId`.
- **Defensive Controls:** Idempotent event deduplication in `SQLiteOfflineQueue`.
- **Regression Tests:** Simulate network drop mid-sync; verify resumption does not produce duplicate events.

---

### Threat 20: Unauthorized Modification of Carrier or HOS Rule Configurations
- **Trust Boundary:** Flutter Driver Client vs. Carrier Management Endpoints.
- **Implementation Trace:** Application operates strictly within the Driver App Scope. No carrier management endpoints are implemented.
- **Existing Safeguards:** Driver application does not contain UI or API adapters for modifying carrier property rules (e.g. 60h/7d vs 70h/8d cycles, 30-minute break exemption).
- **Attacker Prerequisites:** Attempting to alter rules via driver app.
- **Realistic Exploitability:** **ZERO (Out of Scope)**. Rules are assigned server-side by the carrier fleet administrator.
- **Backend Verification Requirements:** Backend RBAC must strictly reject driver accounts from updating carrier configuration rules.
- **Defensive Controls:** Maintain strict Driver App Scope enforcement in mobile codebase.
- **Regression Tests:** Architecture tests verify that administrative config modification endpoints are absent.

## 3. Threat Assessment Matrix & Recommendations

```
  High Risk Tampering Vectors Requiring Immediate Defense:
  ┌─────────────────┬─────────────────────────────────────────────────────────┐
  │ Threat 2        │ Offline Monotonic Time Tampering                        │
  │ Threat 4        │ Replayed / Injected Bluetooth ELD Telemetry             │
  │ Threat 5        │ Fake Vehicle Movement / Speed Suppression               │
  │ Threat 8        │ Modification of Plaintext SQLite Offline Queue          │
  │ Threat 11 & 12  │ Alteration of Odometer & Engine Hours over BLE          │
  └─────────────────┴─────────────────────────────────────────────────────────┘
```

### Strategic Recommendations for FMCSA Compliance Hardening:
1. **Cryptographic ELD Hardware Pairing:** Transition from standard serial BLE UART to authenticated LE Secure Connections with Diffie-Hellman key exchange and hardware-backed session tokens.
2. **Dual-Telemetry Validation:** Correlate BLE odometer and speed values against GPS Doppler speed and distance calculations. Flag diagnostic malfunctions whenever divergence exceeds allowable tolerance.
3. **Database Encryption at Rest:** Implement SQLCipher for `offline_queue.db` and `locations.db`, and `HiveAesCipher` for Hive boxes.
4. **Monotonic Realtime Clocks:** Base offline time verification on hardware monotonic counters (`SystemClock.elapsedRealtime()`) and GPS NMEA time stamps rather than device wall clock time.
